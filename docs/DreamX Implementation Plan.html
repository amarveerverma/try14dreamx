DreamX Implementation Plan

The order of work for building DreamX, an India-first career services marketplace. It follows the PRD's own sequence: specifications first, then GitHub, Vercel and Supabase, then features, with paid launch held behind the payment, legal and privacy gates.

Ground rules

  • No coding before approved specs. The PRD says implementation starts only after the supporting specifications, validation gates and phase plan are approved (PRD §28).
  • Founder approves each phase. Before each phase starts, the team presents the kickoff brief below and waits for approval.
  • Conflicts stop the work. If documents or integrations disagree, record an OPEN DECISION and get approval. Nothing is changed silently.
  • No workarounds for blocked items. No self-built escrow, wallet or split-settlement stand-in while payment validation (V-01 to V-04) is open.
  • Done means evidenced. A feature is complete only with tests, negative security tests where relevant, audit events and a preview deployment (PRD §21.2).
  • No secrets in chat or Git. Credentials live in Vercel and Supabase environment settings. Service-role keys never reach browser code.

About the durations. Week counts below are PROPOSED. They assume a small team of two to three engineers plus the founder, and they must be re-baselined at the end of Phase 0 once the specifications exist.

If that evidence is late, the team continues with P8 design work and P9 to P12 items that do not need money movement, and the pilot falls back to non-transactional flows (discovery, waitlist, assessment).

Phase kickoff brief

Every phase opens with the same one-page brief, taken from PRD §28. The founder approves it before work starts.

  1. Files reviewed
    The PRD sections and specs the phase relies on.
  2. Changes proposed
    Modules, tables, routes and screens to be added.
  3. Dependencies
    Earlier phases, open decisions and validation items.
  4. External dashboard setup
    Accounts, domains, OAuth and provider configuration the founder must do.
  5. Credentials required
    Which values are needed, and where they will be stored. Never pasted into chat.
  6. Verification steps
    Tests to run, preview links and the evidence that proves the exit criteria.
  7. Approved screens
    The Stitch screens for this phase, including empty, loading and error states.

Phase 2: AI co-pilot and credits

Phase 2 starts only after the pilot results are reviewed and the founder gives separate approval. It covers the AI career co-pilot, AI resume, LinkedIn and portfolio tools, interview practice, and the credit economy (₹1 = 10 credits, monthly allowances, credit packs, cashback, an immutable ledger with atomic reservations, cost alerts at 70, 85 and 95 percent, and per-feature pause controls).

Its own ai.md specification, evaluation plan and provider validation come first. Nothing from Phase 2 is built during P0 to P14, though the schema should not make it hard to add later.

This plan sequences the work described in the DreamX PRD V3.0. It does not change any confirmed decision, and it does not certify that any provider, legal or tax requirement has been validated.
